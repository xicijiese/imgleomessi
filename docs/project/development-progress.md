### 2.3 存储与图片处理

- Laravel 文件系统支持 local 和 COS 两种存储模式。
- local 使用 PHP GD 生成展示图和缩略图。
- COS 使用腾讯云数据万象生成展示图和缩略图。
- 展示图最大 2048×2048，缩略图最大 600×600，统一输出 WebP。
- 图片处理通过队列异步执行，不阻塞上传请求。
- 自动发布等待 metadata、hash 和最新派生图任务成功；缺少展示图或缩略图不能发布。
- COS 临时读写、派生图、SHA-256、相似候选和 OCR 按需链路已完成本地/测试验证。

### 2.4 分类安全、用户管理与档案共建者

- 系统保留 8 个主分类；生涯阶段、年份、场景是发布必选分类，其他 5 个主分类可选。
- 系统主分类和系统保留子分类不可删除。
- 普通子分类无图片、相册或子分类引用时可以删除；有引用时显示关联数量并阻止删除。
- 分类删除的并发外键异常会转换为页面通知，不再显示 Livewire 500。
- 档案共建者不开放公开申请、审核或取消申请，只由管理员在私域确认后授予。
- 管理员可以授予、编辑、公开/隐藏和撤销档案共建者资料。
- 授予普通用户共建者身份时，可获得 `editor` 内容角色。
- `editor` 只能管理图片、相册、分类和标签，不能进入用户、订单、支付、审核、系统设置等管理模块。
- `/supporters` 已分区展示运营守护者和档案共建者。
- 用户可在 `/settings/profile` 维护头像；管理员可在 `/admin/users` 代维护头像、治理角色与状态，并查询登录历史和操作审计。

2. 已绑定正常账号按安全策略签发业务令牌；未绑定进入首次登录确认，可选择“已有账号，绑定”或“微信快捷登录/注册”。短挑战5分钟、仅存摘要、单次消费；不得在游客打开页面时静默建账号。
3. 新账号在用户主动确认后以服务端核实的微信身份创建普通user，不强制邮箱、手机号、密码或预先取得真实昵称头像。用户选择手机号快捷授权时，后端独立核实getPhoneNumber授权code并绑定号码，记录验证来源/时间；拒绝或无接口权限不伪造手机号，保留微信身份流程及游客浏览。手机号已被历史账号占用时进入原账号验证/冲突处理，不能自动合并。网站增加“手机号或邮箱＋密码”，保留原邮箱登录；无密码账号在小程序安全设置中通过近期微信身份及所需第二因素验证后设置密码，再以已验证手机号登录网页，不另注册。老用户绑定验证原凭据/第二因素，恢复码原子消费。注册、关联和号码绑定事务防冲突，不使用虚构邮箱或随机已知密码。
4. 首版以Sanctum不透明Bearer令牌管理小程序登录，建议每枚7天有效，不自造JWT/刷新令牌体系；到期重新走微信登录。已启用双重验证的账号在完整登录时仍校验第二因素，避免新增入口绕过网站安全设置。每次请求验证账号状态、绑定有效性及session_version；管理员撤销会话/重置密码后旧API令牌也失效。退出后不立即静默重登，下一次个人操作才引导登录。
5. 安全解绑前确认存在可用的“已验证手机号或邮箱＋已设置密码”等备用凭据；只有微信身份且尚未设置备用方式时，先完善再解绑，防止失联。已设密码账号要求近期密码与启用的第二因素；无密码账号设置首个密码须重新核实微信身份和所需第二因素，不能只凭长期令牌。解绑撤该关联全部令牌，不删除网站账号/互动。不做自助换绑/合并；手机号换号不能改变内部user_id，号码回收风险不能靠自动匹配解决。邮箱/手机变更清除相应验证状态；密码变更使旧令牌失效。

数据只新增必要承载，不复制图库：`wechat_mini_bindings`保存user_id、appid、openid及绑定/最近登录时间，唯一约束为(appid,openid)和(appid,user_id)；UnionID如接口实际返回才作为可空辅助字段，不用于自动合并。Sanctum的`personal_access_tokens`增加绑定引用、签发时session_version；短挑战存Redis并设置TTL与单次消费锁。微信身份只在服务端持有；无解密业务时不长期保存session_key。分享表增量见架构/数据库主文档，不在计划阶段生成或执行迁移。

用户主键仍为users.id，手机号/邮箱/微信身份均为可管理的登录标识，不把可换号手机号当不可变主键。拟增加phone_verified_at及验证来源；历史手填号码不批量置为已验证。账号模型与网站校验需支持真正的可空邮箱/密码；找回密码在无邮箱时不展示不可用的邮件承诺。首版手机号＋密码不等于短信验证码登录，独立短信服务、微信网站扫码及公众号OAuth不因本次调整自动立项。

绑定只增加身份关联，不覆盖原本站昵称头像、简介、公开偏好、密码、角色和权益；同号须验证旧账号，已绑定微信身份优先、不按另一个授权号码切账号。两端主动编辑同一份资料，使用服务端版本校验，过期返回409并提示刷新；下次读取同步，不承诺实时推送。

高风险影响提前说明：新增身份关联和API令牌会扩展认证入口；注销会影响跨端同一账号及有关数据。迁移包含新增表/字段/索引及将email/password兼容性放宽为可空，保留全部原值，不清库、不跑生产Seeder；存在可空新账号后不能down强制非空。先检查收藏/评论/赞助/分享关联和留存，不直接暴露物理删除绕过核查。

### 9.6 图片、状态与分享专项

图片列表只取缩略图，详情取展示图；返回准确派生图尺寸或可计算比例，不能把原图宽高当作缩放后像素尺寸。按需加载、控制已加载页和预览窗口，返回列表恢复筛选/滚动。详情预览优先验证原生能力；必须对当前受限窗口支持缩放/切换，并验证安全保存入口；若平台预览自带保存绕过检查，则使用可控预览组件，不虚构原生API可拦截行为。

保存采用受控展示图接口，经服务端重查后下载到临时文件，再调用系统保存；不把业务Bearer拼进永久URL。若原生预览无法携带鉴权，使用公开受控展示图路径或短期仅限展示图凭证，不使用原图Key。弱网、下载失败、相册权限拒绝、内容下架都显示真实结果；保存授权仅在点击时触发。已经下载或保存到设备的图片无法远程撤回，CDN/客户端缓存也不能保证即时删除；下架后必须阻断新的接口访问并清理相关可控缓存，不作绝对撤回承诺。

分享卡片及码海报统一绑定home/photo/album/topic公开目标。好友卡片只携服务端生成的分享code；海报码的scene放短code，完整映射留服务器，AppID、环境和目标指纹参与缓存键。先核实当前scene长度/字符、页面存在性、开发/体验/正式环境及接口额度后实现；不把Web二维码替换名称当作小程序码。生成任务走现有队列，失败可重试且不重复累计分享收益。

归因需要新增小程序传输适配：服务器签发游客访问凭证，客户端持久化且不伪装成可信身份；落地后取得绑定分享目标的访问回执。仅前台页面可见期间累计至少10秒，隐藏/切后台停止节拍；服务器检查真实时间间隔、凭证轮换、目标有效性与重放。复用账号/第一方身份、全站首次有效归因、排除本人和50人授勋规则；登录绑定后关联网站账号去重。游客普通分享无个人收益；未登录微信身份不能强制拿来替代用户同意登录；匿名跨设备无法保证绝对去重。分享按钮回调、转发次数或截图均不作为成功拉新凭证。

### 9.9 平台准备、发布与回滚

用户负责注册/主体选择、认证和备案资料、名称头像简介与服务类目提交、添加开发者体验者、平台密钥的安全配置、iOS/Android真机配合及审核发布操作；开发负责工程、接口、测试、可审阅体验版、配置与发布说明。默认按单人全栈开发与用户平台/真机配合估算，人员安排变化时重估。现有VPS、MySQL、Redis、COS/CDN、Worker和定时任务继续复用，不额外采购新后台或搜索服务。预算包括平台按主体适用的认证/备案服务费用、媒体流量与存储；以办理时官方后台显示为准，不填猜测价格。

隐私交付需逐项列出微信身份、网站注册资料、头像/评论、通知、推广访问标识的用途、存储位置、接收方和保留/删除规则；只声明实际调用的权限和接口，不强制游客注册来浏览。记录用户主动接受的协议/隐私版本及必要时间依据，按平台实际授权流程实现拒绝、撤回与注销联系入口；客户端只保存必要业务令牌和本机状态，不保存密码/恢复码，退出清除个人缓存，错误上报脱敏。推广明细沿用90天规则，身份/审计留存及注销处理在MP-06/09核验，不编造统一永久保留期限。

注册是当前第一项外部依赖。先核查所选主体与可选类目能否覆盖图片档案、登录、评论互动、头像上传及推广分享，核对是否有额外资质/内容安全接口义务；不将收藏/评论包装成其他类目绕过审核。若平台限制与20页首版冲突，记录具体限制和可审阅调整方案，再由用户决定，不悄悄删功能。未注册期间可开发接口、客户端逻辑和离线演示，不能完成微信真实身份/小程序码/正式发布验收。

正式发布顺序：备份数据库与原配置→部署向后兼容API及增量迁移→重启受影响Worker/更新缓存→配置并核验request/uploadFile/downloadFile涉及域名和全部重定向目标→真机关闭“不校验合法域名”等调试豁免→上传体验版并验收→隐私声明/类目/备案及审核材料核验→平台提审→通过后发布→观察错误率、登录失败、队列和流量。

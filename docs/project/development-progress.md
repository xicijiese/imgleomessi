本文档是项目开发进度的唯一主入口。

后续任何 AI agent 或开发者接手项目时，应优先阅读：

1. `docs/project/development-progress.md`

5. `docs/database/schema.md`

- 项目最终想做成什么。
- 项目被拆成哪些开发阶段。
- 当前正处在哪个阶段。
- 已经完成了什么。

- 本文档记录项目管理视角下的开发进度、阶段目标、决策和风险。

后续每完成一个小阶段，都需要同步更新本文档。

## 项目总目标

建设一个面向梅西影像资料整理、检索和长期考古的图库网站。

项目长期形态是：

- 一个可持续维护的梅西图片档案库。
- 一个支持多维分类、标签、赛事、时间、来源检索的图片资料站。
- 一个未来可以逐步加入轻社交、赞助会员、腾讯云智能处理和微信小程序能力的内容平台。

项目第一原则：先保证资料能被稳定录入、整理、检索和展示，再逐步增加互动和商业化能力。

## 阶段路线图

### Phase 0：项目初始化与规则建立

目标：把项目地基搭好，让后续 AI 开发有明确规则和上下文。

范围：

- 初始化开发前文档。
- 确定技术栈。
- 建立 Git 仓库和提交习惯。
- 建立 AI agent 协作规则。
- 初始化 Laravel 项目骨架。
- 配置本地开发环境。
- 配置后台中文化。

状态：已完成。

### Phase 1：图库核心 MVP

目标：完成图库最小可用闭环。

范围：

- 图片数据模型。
- 相册/专题模型。
- 图片分类模型。
- 标签模型。
- 人物模型。
- 赛事/事件模型。
- 图片来源字段。
- 后台图片上传和管理。
- 后台批量上传到相册。
- 后台批量整理图片。
- 后台相册/专题管理。
- 后台分类、标签、赛事等基础字典管理。
- 前台图片列表页。
- 前台图片详情页。
- 基础关键词搜索。
- 基础筛选：分类、标签、时间、赛事。
- 少量测试数据录入。

第一版成功标准：

- 管理员可以从后台上传一张图片并填写基础资料。
- 图片可以在前台列表中展示。
- 图片可以进入详情页查看。
- 用户可以通过基础条件找到这张图片。
- 整个流程不依赖评论、会员、小程序或 AI 图片能力。

状态：当前阶段。

### Phase 2：图库检索与资料增强

目标：让图库更适合长期考古和高效查找。

范围：

- 高级筛选组合。
- 图片清晰度、尺寸、横竖图、水印状态。
- 来源可信度和转载说明。
- 时间轴浏览。
- 赛事专题页。
- 球队/赛季/对手维度。
- 批量编辑图片信息。
- 后台批量导入优化。
- 图片重复提示的基础人工流程。

状态：未开始。

### Phase 3：腾讯云 COS 与数据万象接入

目标：让图片存储和智能处理逐步接入真实云服务。

范围：

- 腾讯云 COS 存储桶配置。
- 图片上传到 COS。
- 图片访问域名和防盗链策略。
- 数据万象基础图片处理。
- EXIF 读取。
- OCR 识别结果存储。
- 感知哈希字段预留和计算。
- 相似图去重工作流。
- 以图搜图可行性验证。

注意：Phase 1 不依赖本阶段。第一版可以先用本地存储或模拟字段完成业务闭环。

状态：未开始。

### Phase 4：轻社交功能

目标：在图库稳定后，增加低强度互动能力。

范围：

- 用户注册和登录体验优化。
- 评论。
- 点赞。
- 收藏。
- 分享。
- 举报。
- 内容审核。
- 用户个人页的基础形态。

注意：轻社交要控制边界，不能让项目从图库站变成重社区。

状态：未开始。

### Phase 5：会员与赞助

目标：支持网站可持续运营，不把 VIP 设计成图片版权售卖。

范围：

- 普通用户。
- VIP 用户。
- 赞助记录。
- 微信支付。
- 赞助权益展示。
- 后台会员管理。
- 支付回调和订单状态。

原则：

- VIP 是赞助支持，不是购买图片版权。
- 第一版不做付费内容墙。
- 涉及支付前必须先补充合规说明和退款/异常处理流程。

状态：未开始。

### Phase 6：微信小程序可行性与实现

目标：评估并实现适合微信生态的轻量图库访问入口。

范围：

- 小程序审核风险评估。
- 内容合规策略。
- 小程序页面范围。
- 小程序 API 接口。
- 登录与账号绑定。
- 分享链路。

注意：小程序审核存在不确定性，不能作为网站第一版上线前置条件。

状态：未开始。

### Phase 7：上线、运维、备份与监控

目标：让网站能稳定运行并可恢复。

范围：

- CentOS + 宝塔部署。
- PHP、Nginx、MySQL、Redis 环境。
- 队列任务。
- 定时任务。
- 备份策略。
- COS 数据备份策略。
- 日志管理。
- 错误监控。
- 上线检查清单。

状态：未开始。

## 当前阶段

当前阶段：Phase 1，图库核心 MVP。

当前目标：先完成一个能持续录入、管理、浏览和检索图片的梅西图库核心版本。

当前重点：

- 确认图片数据模型。
- 创建图库核心数据表。
- 创建后台管理资源。
- 实现前台列表、详情和基础检索。
- 分类模型采用 7 个必选主分类 + 子分类 + 多标签。
- 相册/专题用于批量组织图片，并可设置默认分类。

## 当前版本目标

第一版 MVP 只做“图库核心闭环”。

核心闭环包括：

- 管理员可以登录后台。
- 管理员可以上传图片。
- 管理员可以管理图片基础信息。
- 管理员可以创建相册/专题，并为相册选择默认分类。
- 管理员可以在相册中批量上传图片。
- 批量上传完成后，管理员可以进入批量整理页面，逐图快速补充标题、说明、标签和发布状态；图片说明和标签都可以为空。
- 图片上传后由系统自动重命名，格式为 `YYYYMMDD-HHmmss-6位随机码.原扩展名`。
- 图片标题默认使用系统重命名后的文件名，发布前可修改，也可不修改；标题不允许为空。
- 数据库保留用户上传时的原始文件名，用于后续追溯线索。
- 图片上传后默认进入草稿/待整理状态，不在前台公开展示。
- 管理员或编辑点击发布后，图片立即发布并对前台可见。
- 图片加入相册时，自动继承相册默认分类。
- 相册内图片不允许额外手动补充分类，分类完全跟随相册。
- 单独上传图片时，图片必须自行选择 7 个主分类下的子分类。
- 管理员可以维护分类、标签、人物、赛事、时间、来源等检索维度。
- 前台用户可以浏览图片列表。
- 前台用户可以进入图片详情页。
- 前台用户可以通过关键词、分类、标签、时间、赛事等基础条件检索图片。

第一版暂不做：

- 评论。
- 点赞。
- 转发。
- VIP 会员。
- 充值赞助。
- 微信小程序。
- OCR 识别。
- 感知哈希去重。
- 相似图去重。
- 以图搜图。
- 自动从腾讯云数据万象回写全部 AI 识别结果。

这些能力不是放弃，而是等图库核心闭环稳定后，再按阶段加入。

## 已确定决策

- 本文档作为项目路线图与开发进度的唯一主入口。
- 第一版 MVP 只做图库核心闭环。
- Phase 1 只创建图库核心表，社交、赞助、支付、AI 分析和系统任务相关表先保留在文档中，不写 migration。
- Phase 1 固定 7 个必选主分类：生涯阶段、赛事、赛季、年份、场景、图片类型、来源平台。
- Phase 1 不允许后台随意新增第 8 个主分类；后续如需新增主分类，必须先更新产品文档、数据库约束和旧数据补齐方案。
- 后台允许在 7 个固定主分类下自由新增、编辑和排序子分类。
- 每个主分类都必须预置 `待补充` 子分类，用于资料暂时不完整、需要后续考古补充的图片。
- 若后续用户在评论或其他反馈中补充了可靠信息，管理员或编辑可以将 `待补充` 修改为已有子分类，或先新增子分类再重新选择。
- Phase 1 图片支持多分类，本质是每个主分类选择一个子分类；标签独立存在，图片也支持多标签。
- Phase 1 加入相册/专题功能；相册必须选择 7 个主分类下的子分类，图片加入相册时分类完全同步相册，相册内图片不额外补充分类。
- 单独上传图片时，图片必须自行选择 7 个主分类下的子分类，并可设置多个标签。
- Phase 1 允许后台自由新增、编辑和排序标签，但每个标签必须归属一个标签类型。
- Phase 1 预置 8 个标签类型：动作、情绪、画质、人物关系、荣誉、画面内容、服装/装备、地点。
- Phase 1 图片标签可以为空；标签用于补充细节，不阻塞整理和发布。
- Phase 1 上传图片时不做重复检测、不做哈希拦截、不做感知哈希检测、不做相似图检测；上传一次就是一条新的图片记录。
- 同一视觉图片可以重复上传到不同相册，各自作为独立图片记录管理，各自跟随所在相册分类并维护自己的标题、说明和标签。
- 相似图去重作为后续后台管理能力，不进入 Phase 1 上传流程。
- Phase 1 必须支持批量上传到相册；上传完成后进入批量整理页面，支持逐图编辑标题、说明、标签和发布状态。
- 批量整理页面不提供相册内图片分类编辑，分类由相册统一决定。
- Phase 1 图片上传后默认进入草稿/待整理状态；点击发布后立即进入已发布状态并对前台可见。
- Phase 1 图片上传后系统自动重命名文件，格式为 `YYYYMMDD-HHmmss-6位随机码.原扩展名`；标题默认使用重命名后的文件名，发布前可改可不改；标题不允许为空；数据库保留原始文件名。
- Phase 1 图片说明可以为空；说明用于补充背景、考古线索或来源备注，不阻塞整理和发布。
- 评论、点赞、转发、VIP、充值赞助、微信小程序、OCR、相似图去重和以图搜图都不进入第一版。
- 技术栈采用 Laravel + Inertia.js + Vue 3 + TypeScript + Tailwind CSS。
- 后台第一版使用 Filament，不自建后台管理系统。
- 本地开发阶段先用 SQLite，降低新手环境搭建成本。
- 后台默认语言使用简体中文。
- 后续涉及腾讯云 COS、数据万象、微信支付、短信等第三方服务时，先做接口边界和配置文档，再接真实服务。

## 风险与注意事项

- 项目容易功能膨胀，所有新增功能必须先判断是否影响 MVP 核心闭环。
- 图片版权、来源和转载说明要尽早设计字段，避免后期补数据成本过高。
- 图片分类体系会决定后续检索体验，不能只按“照片类型”粗略分类。
- 微信小程序审核存在不确定性，不能作为第一版上线依赖。
- 以图搜图、相似图去重和 OCR 都属于增强能力，不能阻塞第一版图库管理上线。
- 支付和会员涉及资金链路，必须在功能设计、合规说明、异常处理明确后再开发。
- 后续 AI agent 开发必须先阅读本文档、`CONTEXT.md` 和相关 PRD/架构文档，再开始修改代码。

### 2.3 存储与图片处理

- Laravel 文件系统支持 local 和 COS 两种存储模式。
- local 使用 PHP GD 生成展示图和缩略图。
- COS 使用腾讯云数据万象生成展示图和缩略图。
- 展示图最大 2048×2048，缩略图最大 600×600，统一输出 WebP。
- 图片处理通过队列异步执行，不阻塞上传请求。
- 自动发布等待 metadata、hash 和最新派生图任务成功；缺少展示图或缩略图不能发布。
- COS 临时读写、派生图、SHA-256、相似候选和 OCR 按需链路已完成本地/测试验证。

### 2.4 分类安全、用户管理与档案共建者

- 系统保留 8 个主分类；生涯阶段、年份、场景是发布必选分类，其他 5 个主分类可选。
- 系统主分类和系统保留子分类不可删除。
- 普通子分类无图片、相册或子分类引用时可以删除；有引用时显示关联数量并阻止删除。
- 分类删除的并发外键异常会转换为页面通知，不再显示 Livewire 500。
- 档案共建者不开放公开申请、审核或取消申请，只由管理员在私域确认后授予。
- 管理员可以授予、编辑、公开/隐藏和撤销档案共建者资料。
- 授予普通用户共建者身份时，可获得 `editor` 内容角色。
- `editor` 只能管理图片、相册、分类和标签，不能进入用户、订单、支付、审核、系统设置等管理模块。
- `/supporters` 已分区展示运营守护者和档案共建者。

## 4. 当前规则速查

### 4.1 分类与来源

- 当前使用 8 个固定主分类，不随意新增根分类。
- 生涯阶段、年份、场景为发布必选分类。
- 图片来源直接存入 `photos.source_url`，可为空。
- 来源平台通过“来源平台”主分类维护。
- 对手名称作为普通标签维护，不再使用独立 opponents 表。
- 不存在独立 Source 后台 Resource。

### 4.2 图片处理与发布

- 上传只创建图片和上传任务记录，耗时操作进入队列。
- local 生成派生图使用 PHP GD；COS 生成派生图使用数据万象。
- OCR 默认关闭，只有管理员按需触发。
- OCR 失败不阻塞上传和发布。
- 智能标签不再参与当前流程。
- 自动发布只依赖 metadata、hash、派生图和业务发布条件。

### 4.3 用户、角色与共建者

| 身份 | 当前权限 |
|---|---|
| 普通用户 | 前台浏览、账号资料和普通互动 |
| `editor` | 普通用户权限 + 图片、相册、分类、标签维护 |
| `admin` | 管理员后台资源和档案共建者管理 |
| 档案共建者 | 展示身份；通常同时授予 `editor` 内容角色，不是独立管理员角色 |
| 运营守护者 | 赞助展示身份，不等于后台角色 |

共建者资料只能由管理员在后台授予、编辑和撤销，前台不提供申请入口。

### 4.4 分类删除

- 有图片、相册或子分类引用时禁止删除。
- 删除失败必须显示业务提示，不得显示页面级 500。
- 系统分类不可删除。
- 后续如需长期保留历史数据，应优先隐藏而不是删除。

## 7. 开发流程硬规则

所有新功能统一遵循：

**确认稿 → 用户确认 → 垂直切片开发 → 测试/构建 → 文档同步 → 下一切片确认稿**

开发前必须明确：

- 页面和路由。
- 数据表和字段。
- 按钮、筛选、排序和状态。
- 用户角色和权限边界。
- 验收标准。
- UI/UX 交互方式。

编号不是进度依据。后续必须使用功能名和路由描述，例如“前台图库列表 `/photos`”，不能只使用历史编号判断当前任务。

# 开发进度记录

本文档用于记录项目当前阶段、已完成事项、正在推进的工作、下一步计划和待确认问题。

它和 `CHANGELOG.md` 的区别：

- `CHANGELOG.md` 记录代码和文档层面的变更。
- 本文档记录项目管理视角下的开发进度、阶段目标、决策和风险。

后续每完成一个小阶段，都需要同步更新本文档。

## 当前阶段

阶段：MVP 范围确认与图库核心闭环开发前准备

当前目标：先完成一个能持续录入、管理、浏览和检索图片的梅西图库核心版本。

## 当前版本目标

第一版 MVP 只做“图库核心闭环”。

核心闭环包括：

- 管理员可以登录后台。
- 管理员可以上传图片。
- 管理员可以管理图片基础信息。
- 管理员可以维护分类、标签、人物、赛事、时间、来源等检索维度。
- 前台用户可以浏览图片列表。
- 前台用户可以进入图片详情页。
- 前台用户可以通过关键词、分类、标签、时间、赛事等基础条件检索图片。

第一版暂不做：

- 评论。
- 点赞。
- 转发。
- VIP 会员。
- 充值赞助。
- 微信小程序。
- OCR 识别。
- 感知哈希去重。
- 相似图去重。
- 以图搜图。
- 自动从腾讯云数据万象回写全部 AI 识别结果。

这些能力不是放弃，而是等图库核心闭环稳定后，再按阶段加入。

## 待确认问题

- 图片是否必须支持“一图多分类”。
- 标签是否允许后台自由创建，还是先用固定标签。
- 赛事维度是否要拆成赛事、赛季、球队、对手、比赛日期。
- 图片来源是否必须记录原始链接、发布平台、作者、转载说明。
- 图片是否需要区分清晰度、尺寸、横竖图、是否水印。
- 前台是否允许未登录用户浏览全部图片。
- 图片详情页是否需要显示下载按钮。
- 是否需要在第一版加入“仅管理员可见”的内部备注字段。

## 已确定决策

- 第一版 MVP 只做图库核心闭环。
- 评论、点赞、转发、VIP、充值赞助、微信小程序、OCR、相似图去重和以图搜图都不进入第一版。
- 技术栈采用 Laravel + Inertia.js + Vue 3 + TypeScript + Tailwind CSS。
- 后台第一版使用 Filament，不自建后台管理系统。
- 本地开发阶段先用 SQLite，降低新手环境搭建成本。
- 后台默认语言使用简体中文。
- 后续涉及腾讯云 COS、数据万象、微信支付、短信等第三方服务时，先做接口边界和配置文档，再接真实服务。

## 风险与注意事项

- 项目容易功能膨胀，所有新增功能必须先判断是否影响 MVP 核心闭环。
- 图片版权、来源和转载说明要尽早设计字段，避免后期补数据成本过高。
- 图片分类体系会决定后续检索体验，不能只按“照片类型”粗略分类。
- 微信小程序审核存在不确定性，不能作为第一版上线依赖。
- 以图搜图、相似图去重和 OCR 都属于增强能力，不能阻塞第一版图库管理上线。
- 后续 AI agent 开发必须先阅读本文档、`CONTEXT.md` 和相关 PRD/架构文档，再开始修改代码。

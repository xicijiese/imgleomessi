# PRD：梅西影像档案库

## 1. 问题陈述

梅西相关图片资料散落在社交平台、新闻网站、球迷账号和个人网盘中，存在时间不准、来源不清、分类混乱、重复图多、检索困难、高清版本难找等问题。用户想建立一个长期可维护的图库站，用于后续查阅、考古和中文球迷资料沉淀。

## 2. 产品定位

产品是“梅西影像档案库 + 轻社交 + 赞助支持”。

它不是官方站，不是后援会，不做版权内容售卖。赞助会员的含义是支持网站可持续维护，不是购买图片版权或解锁盗版图片。

## 3. 用户角色

| 角色 | 核心目标 | 主要权限 |
|---|---|---|
| 游客 | 浏览公开图片与相册 | 浏览、搜索基础公开内容、分享公开页面 |
| 普通用户 | 收藏、互动、参与轻社交 | 登录、收藏、点赞、评论、举报、分享 |
| 支持者 | 赞助网站维护 | 普通用户权限、支持者徽章、支持者页展示、可选无广告/更高配额 |
| 编辑员 | 维护图片资料 | 上传图片、编辑图片元数据、管理相册、处理待考证资料 |
| 管理员 | 管理全站 | 用户、权限、订单、评论审核、系统设置、数据处理任务 |

## 4. 功能优先级

### P0：第一版必须完成

1. 管理员/编辑员后台登录。
2. 图片上传到 COS。
3. 图片档案基础字段：标题、日期、相册、球队、赛事、标签、来源、版权状态、审核状态。
4. 相册管理：事件相册、专题相册、生涯阶段。
5. 前台图库浏览：首页、相册页、图片详情页、搜索页。
6. 基础检索：关键词、年份、球队、赛事、标签、相册。
7. 图片缩略图与展示图。
8. 本地任务和开发规范文档。

### P1：第二阶段

1. 普通用户注册登录。
2. 收藏、点赞、评论。
3. 评论审核、举报、封禁、敏感词基础过滤。
4. 支持者赞助：订单、支付回调、支持者身份、支持者页面。
5. 图片入库队列：EXIF、哈希、OCR、质量评分。
6. 后台重复图提示。
7. sitemap、SEO 基础优化。

### P2：第三阶段

1. 高级搜索：组合筛选、清晰度、来源、版权状态、人物同框。
2. Meilisearch 或 Typesense。
3. 以图搜图、以文搜图。
4. 相似图分组。
5. 微信小程序只读版：浏览、搜索、收藏、评论。
6. 投稿表单：普通用户提交线索，不直接公开上传。

## 5. 用户故事

1. 作为游客，我想按年份查看梅西图片，这样可以快速回到某个生涯阶段。
2. 作为游客，我想进入某场比赛的相册，这样可以按事件考古。
3. 作为普通用户，我想收藏图片，这样以后可以快速找回。
4. 作为普通用户，我想评论图片，这样可以补充背景信息或参与讨论。
5. 作为普通用户，我想举报不当评论，这样社区内容能被维护。
6. 作为支持者，我想通过赞助支持网站，这样站点能长期维护。
7. 作为支持者，我想显示支持者徽章，这样能表达我对项目的支持。
8. 作为编辑员，我想批量上传图片，这样能高效整理历史素材。
9. 作为编辑员，我想给图片添加赛事、球队和标签，这样前台用户能检索。
10. 作为编辑员，我想看到重复图和相似图提示，这样能减少图库污染。
11. 作为管理员，我想审核评论，这样能降低 UGC 风险。
12. 作为管理员，我想查看赞助订单和支付回调，这样能排查支付问题。

## 6. 不做什么

第一版不做：

- 普通用户直接公开上传图片。
- 图片版权交易。
- 付费解锁原图。
- 完整论坛、私信、关注流。
- 自动识别梅西以外所有人物并自动发布。
- 微信小程序支付闭环。
- APP。
- 多语言。
- 商业图库授权。

## 7. 验收标准

P0 完成时，应能做到：

- 管理员能上传并管理图片。
- 前台用户能按相册、年份、球队、赛事、标签检索图片。
- 每张图片有来源和版权状态字段。
- 图片文件不存放在服务器本地公开目录，而是走 COS/CDN。
- 后续 P1/P2 功能有清晰任务入口。

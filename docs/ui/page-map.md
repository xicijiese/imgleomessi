# 页面清单与 UI 映射

## 当前状态

本文档是唯一 UI/页面文档，负责承载前台页面清单、后台页面清单、页面归属规则、P0 页面开发规格和 UI 质量要求。

页面与 P0 规格已经完成整体确认。后续恢复开发时，每个切片开发前必须一次性确认该页面或功能的字段、按钮、筛选、排序、状态、权限、验收标准、交互方式和 UI/UX 风格，不允许一轮只问一个细碎问题。

## 当前生效规则（2026-09-12）

- 前台页脚由 `resources/js/app.ts` 统一渲染，除 `/me` 及 `/me/*` 个人中心页面外，所有前台页面（包括公开内容页、认证页和账号设置页）都显示 `PublicFooter`；页面模板不再重复挂载页脚。
- “上传批次 / 批量整理”页面现为只读“上传任务”记录页，仅展示上传结果、失败原因和处理状态，并跳转到图片管理；不提供单张或批量编辑。
- 图片管理是图片元数据和状态的唯一编辑入口，列表支持批量修改分类、标签、来源链接、版权状态、发布状态、草稿和归档。
- 图片管理列表缩略图使用真实图片，悬停可预览较大的展示图；智能标签入口移除，OCR 保留为手动按需操作。
- local 和 COS 都必须通过异步派生图任务生成展示图与缩略图；处理失败时在后台任务中显示原因，图片不能发布。local 使用 PHP GD，COS 使用数据万象，输出规格和字段保持一致。
- 图片管理列表每行只展示一个真实缩略图，支持悬停预览展示图；不能把存储地址当作缩略图，也不能上下重复渲染同一图片。
- 图片管理列表提供单张发布按钮和批量发布；草稿可发布，已发布和已归档记录的发布按钮置灰。编辑窗口中的发布状态、发布时间是系统状态展示，不作为普通字段修改。
- 上传任务页面只查看上传结果和处理状态；“生成展示图/缩略图”、编辑、发布和批量修改均在图片管理完成。
- 分类表单按主分类分别展示子分类选择器；生涯阶段、年份、场景旁显示红色 `*`，其他主分类标注为可选；相册为可选关联，放在分类区域底部。
- 相册创建和编辑使用同样的 8 个主分类独立选择器；生涯阶段、年份、场景为必填，其他主分类可选，保存后同步到 `album_category`。

## 1. UI 原则

产品是内容密集型图库，不做营销型落地页。第一屏应直接让用户进入浏览、搜索和相册，而不是大段品牌宣传。

前台技术实现采用 Inertia.js + Vue 3 + TypeScript + Tailwind CSS。前台不使用重型后台组件库，优先定制图片卡片、筛选面板、相册头部等产品专属组件；评论区属于 P1 后续能力。

设计关键词：

- 内容优先
- 清晰检索
- 移动端友好
- 克制、资料库感
- 图片网格性能优先
- 轻社交不喧宾夺主

### 1.1 前台色彩语义系统

前台默认采用 Happy Hues Palette 3 作为基础色彩参考，但不能把它简化成全站一套固定颜色。落地时按区块明暗、卡片层级和状态语义分别使用。

基础色值：

| 色彩角色 | 色值 | 用途 |
|---|---|---|
| 主背景 | `#fffffe` | 页面默认背景、卡片背景、表单输入背景。 |
| 浅蓝区块背景 | `#d8eefe` | 首页搜索区、专题/相册推荐区、空状态、柔和提示区。 |
| 主标题 / 深色主体 | `#094067` | 导航、页面标题、区块标题、深色区块背景、重要元数据标题。 |
| 正文辅助文字 | `#5f6c7b` | 描述、来源、日期、版权说明、次级元数据。 |
| 主按钮 / 链接强调 | `#3da9fc` | 主按钮、搜索按钮、当前筛选、链接、可点击强调。 |
| 次级蓝灰 | `#90b4ce` | 边框、分割线、标签底色、次级按钮、深色区块正文。 |
| 少量强调红 | `#ef4565` | 精选、热门、错误、版权风险、重要提示；禁止大面积使用。 |

区块用法：

| 场景 | 背景 | 标题 | 正文 | 强调/按钮 |
|---|---|---|---|---|
| 默认浅色页面 | `#fffffe` | `#094067` | `#5f6c7b` | `#3da9fc` |
| 浅蓝内容区 | `#d8eefe` | `#094067` | `#5f6c7b` | `#3da9fc` |
| 白色卡片 | `#fffffe` | `#094067` | `#5f6c7b` | `#3da9fc` 或 `#90b4ce` |
| 深蓝强调区 | `#094067` | `#fffffe` | `#d8eefe` 或 `#90b4ce` | `#3da9fc`，少量 `#ef4565` |
| 警示 / 重点提示 | `#fffffe` 或轻量描边 | `#094067` | `#5f6c7b` | `#ef4565` |

使用约束：

- 深蓝背景上不要直接使用 `#5f6c7b` 作为正文，优先使用 `#d8eefe` 或 `#90b4ce`，保证可读性。
- `#ef4565` 只做小面积强调，不用于大面积背景或主要导航。
- 前台整体保持蓝白清爽资料库感，不做球迷论坛式高饱和大红大蓝，也不做营销落地页式渐变堆叠。
- 首页可以使用浅蓝区块和少量深蓝强调区形成层次；图库列表和搜索页以白底、稳定网格和清晰筛选为主。
- 具体按钮尺寸、卡片样式、模块间距和首页首屏结构，在首页 UI/UX 细化时再确认。

参考来源：https://www.happyhues.co/palettes/3

#### 3.2.1 首页 UI/UX 确认稿

首页参考 ThemeGoods Photography Home 4 的摄影首页结构和交互气质，同时改造成梅西影像档案库的内容入口。实现时不使用 WordPress 主题代码，使用 Laravel + Inertia + Vue + Tailwind 重写，整体配色遵循第 1.1 节色彩语义系统。

首页模块顺序：

1. 导航栏。
2. 头图轮播。
3. 精选相册模块。
4. 最新照片模块。
5. 专题模块。
6. 页脚。

导航栏：

- 桌面端模仿示例站透明顶部导航，覆盖在头图上；页面滚动后切换为白底或浅色固定导航，文字切换为深蓝色。
- 导航完整顺序确定为：`首页 / 图库 / 相册 / 专题 / 时间线 / 排行榜 / 支持本站 / 个人中心`；示例站的 Shop 改为 `个人中心`。P0 未实现的入口先不在前台显示，时间线归档保留为 P1，待 P1 页面完成后再打开导航入口。
- LOGO 右侧、个人中心左侧放搜索栏；搜索栏提交后进入搜索页并回显关键词。
- 移动端使用按钮抽屉式导航：顶部保留 LOGO、搜索入口和菜单按钮，点击菜单按钮后以抽屉方式展开导航、搜索入口和个人中心入口。

头图轮播：

- 模仿示例站大图首屏轮播，使用 3 到 5 张精选头图。
- 支持淡入淡出、轻微缩放或 Ken Burns 效果；动画只服务图片浏览氛围，不做复杂装饰。
- 每张头图可配置图片、标题、副标题、按钮文字、跳转链接、排序和启用状态。
- 桌面端文字覆盖在图片左中区域或视觉安全区域；移动端降低头图高度，标题、搜索入口和按钮不得遮挡图片主体。
- 深色遮罩使用 `#094067` 的透明层，文字使用 `#fffffe`，主要按钮或链接使用 `#3da9fc`。

分类模块：

- 上方使用子分类导航，默认只显示“全部”；后台可选择最多 7 个公开子分类、设置显示数量、排序和是否启用。
- 子分类导航点击后留在首页内切换精选相册，不直接跳出首页；“更多”与导航水平对齐并进入相册列表页。
- 下方使用相册封面网格：桌面端 3 列，平板端 2 列，手机端 1 列；封面默认无标题和遮罩，hover 时显示底部标题和半透明遮罩，移动端标题常态可读。
- 精选相册默认先展示后台标记的精选相册，再按最新发布相册补足；不配置指定图片、指定相册或自定义导航名。
- 相册卡片 hover 时图片轻微放大、遮罩加深并显示底部标题；移动端无 hover 时标题常态可读。
- 移动端没有 hover，标题必须常态可读，分类导航横向滑动。

最新照片模块：

- 参考 ThemeGoods Gallery 3 Columns Contained，采用居中 contained 三列画廊，不再使用混合网格。
- 桌面端 3 列等宽图片网格，容器最大宽度约 1140px 到 1200px；平板端 2 列；手机端 1 列。
- 展示最近发布的公开图片，不展示后台草稿或待整理图片；单独上传且已发布的图片也进入该模块。
- 支持后台指定置顶若干张图片，再自动补足最新发布图片；后台可设置模块标题、显示数量、排序方式和启用状态。
- 图片交互模仿示例画廊的简洁感：hover 时只保留轻微放大或明暗变化，不显示标题、日期、分类或其他文字信息，点击进入通用图片详情页。
- P0 点击优先进入图片详情页；灯箱能力可预留，是否在首页直接打开灯箱后续再确认。
- 图片容器必须有稳定宽高比或明确尺寸，避免加载跳动；移动端不强行 masonry，优先清晰和稳定。

专题模块：

- 模仿示例站图二的横向图片带视觉和交互，但改为专题入口，不作为纯社媒图片流。
- 后台可指定展示哪些专题、展示数量、排序、封面图和启用状态；指定项不足时可按推荐专题自动补足。
- 桌面端专题格横向铺开，图片之间不做复杂卡片嵌套；hover 时轻微放大、遮罩加深、标题增强。
- 专题名称默认放在每格图片中央，常态可见，加轻微深色遮罩；移动端改为横向滑动卡片或两列卡片，专题名放在图片底部遮罩层或中央安全区域。
- 专题格点击后进入对应专题详情页；因此专题详情页进入 P0 首页配套范围。

页脚：

- 模仿示例站简洁页脚，保持轻量，不做复杂营销区。
- 社交平台改为中文语境，可配置微博、B 站、小红书、抖音、微信公众号、邮箱等。
- 后台可配置社媒名称、链接、图标、排序、是否显示、版权文字、备案信息、关于本站和版权说明入口。

后台配置边界：

- 首页配置归入后台 `系统设置 -> 首页配置`，不新增后台主入口；P0 使用通用 `settings` 表保存结构化 JSON 配置。
- P0 做固定首页结构的可配置后台，不做拖拽式 CMS 页面搭建器。
- 每个模块至少支持：模块标题、启用状态、显示数量、排序、手动指定展示项、自动补足规则；首页内容模块允许后台关闭，导航和页脚默认保留但内容可编辑。
- 手动指定的图片、相册和专题必须是可公开展示内容；草稿、隐藏、归档和受限内容不能被公开模块选中。

已确认补充规则：

- 首页每个模块都需要空状态、加载骨架屏、图片失败占位和无配置时的稳定兜底逻辑。

- 收藏：登录用户可收藏 / 取消收藏；同一用户对同一图片只保留一条收藏记录；游客点击后走登录边界；P1-4 不做公开收藏数和收藏列表页，我的收藏 后续用户中心切片再做。

- 交互体验：收藏 / 点赞按钮必须采用前端乐观更新，并通过 JSON 小响应确认最终状态；不得用 Inertia 表单提交导致整页刷新，不得在收藏 / 点赞按钮上显示等待光标、加载文案或短暂禁用态。
- 分享：游客和登录用户都可使用分享入口；优先调用浏览器原生分享能力，不支持时复制当前详情页 URL；分享成功或复制成功后记录分享事件，游客分享记录不绑定用户。
- P1-4 只记录基础数据：图片、用户可空、分享渠道、页面 URL、IP、UA 和创建时间；不做微信/微博第三方 API、分享海报、短链接、分享返利、复杂动态流、后台互动管理、异常刷赞处理或排行榜管理。

- 永久不做 / 默认禁做：前台公开图片详情默认下载按钮；分享返利默认不做，除非后续被明确重新立项并完成合规确认。

#### 3.3.2 P1-5 图片评论与信息补充 / 纠错投稿开发前确认稿（已确认，已完成）

本确认稿只覆盖图片详情页 `/photos/{uuid}` 的评论提交、评论展示基础、图片信息补充和纠错投稿基础能力。P1-5 的目标是让登录用户可以围绕某张公开图片参与讨论、补充资料或提交纠错线索；所有用户生成内容默认进入待审核状态，不绕过审核直接公开。完整后台审核队列、举报、封禁、敏感词过滤、异常用户治理和评论排行榜放到 P1-6 及后续独立切片。

开发范围：

- 普通评论：登录用户可在图片详情页提交普通评论；评论用于讨论图片、赛事背景、个人记忆和资料补充之外的交流。
- 图片信息补充 / 纠错投稿：登录用户可在图片详情页提交结构化线索，指出标题、日期、赛事、球队、人物同框、来源、版权备注、分类、标签等可能需要补充或修正的信息。
- 评论展示：图片详情页展示已发布的普通评论；待审核、拒绝、删除状态不公开展示。
- 提交反馈：用户提交后前台即时显示“已提交，等待审核”的成功反馈，不把待审核内容混入公开评论列表。
- 基础数据记录：记录图片、用户、类型、内容、状态、父评论、创建时间和更新时间；纠错类额外记录建议字段、建议值、证据链接、补充说明等结构化信息。
- 登录边界：游客和未登录用户可以浏览已发布评论，但提交评论或纠错时必须登录。
- 后台最小可见性：P1-5 先保证评论/纠错记录入库；完整审核操作、批量处理、敏感词、封禁和举报不在本切片做，放到 P1-6。
- 本地演示数据：`LocalGalleryDemoSeeder` 生成 4 个模拟用户，并为测试图片生成若干已发布普通评论和待审核纠错记录，用于前台评论区效果验收。

建议数据模型：

- `comments` 表作为统一评论表，`type` 区分 `discussion` 普通评论和 `correction` 图片信息补充/纠错。
- `status` 使用 `pending`、`published`、`rejected`、`deleted`；用户新提交默认 `pending`。
- `photo_id` 必填，只允许对公开图片提交；`user_id` 必填，游客不能提交。
- `parent_id` 预留回复关系；P1-5 不做多层楼中楼，只允许后续用于一层回复。
- `content` 必填，长度建议 2-1000 字；P1-5 不支持图片、附件、富文本、Markdown 或表情包上传。
- 纠错类建议增加 `correction_field`、`suggested_value`、`evidence_url` 或 `meta` JSON，用于记录用户指出的字段、建议内容和证据链接；前台不要求用户填写全部结构化项，只要内容说明清楚即可。
- `like_count` 暂时保留字段但 P1-5 不做评论点赞。

图片详情页展示：

- 评论区位置放在主图和基础信息之后、相关推荐之前；如果后续加入相似图推荐，位置再单独确认，当前不调整相似图推荐规划。
- 评论区顶部使用两个清晰入口：`评论` 和 `补充 / 纠错`，可以是 tabs 或分段按钮。
- 默认展示已发布普通评论列表，按创建时间倒序或正序需本次确认；我的建议是倒序，用户先看到最新讨论。
- 评论项展示：用户昵称、发布时间、评论内容；不展示邮箱、IP、UA、用户内部状态和后台处理备注。
- 纠错类内容默认不公开展示在评论流里；提交后只给提交者成功反馈，后续审核通过后由管理员/编辑员修正图片资料或转为公开说明。
- 无评论时显示稳定空状态，例如“还没有公开评论”。
- 评论加载失败时显示轻量错误状态，并提供重试按钮。

按钮与入口：

- `发表评论`：仅登录用户可用；未登录点击跳转登录。
- `提交补充 / 纠错`：仅登录用户可用；未登录点击跳转登录。
- `取消`：关闭输入状态，不保留未提交内容。
- `提交中`：提交按钮只在请求中短暂禁用，不显示全页加载，不刷新详情页。
- 暂不做：评论点赞、评论回复、评论删除、评论编辑、评论举报、评论排序切换、评论分页复杂筛选。

权限与状态：

- 游客：可浏览公开图片详情和已发布普通评论；不能提交评论或纠错。
- 登录用户：可提交普通评论和补充/纠错；提交后状态为待审核。
- 管理员 / 编辑员：P1-5 只保证后续可以看到数据；完整审核、发布、拒绝、隐藏、删除和处理记录放到 P1-6。
- 草稿、归档、受限使用、请求下架和不存在的图片不允许提交评论或纠错，继续返回 404。
- 被删除或拒绝的评论不在前台公开展示。

交互与 UI/UX：

- 延续当前图片详情页克制资料库风格，评论区不做社交平台式强刺激动态流。
- 输入框常态不占用太多空间；点击入口后展开表单。
- 评论和纠错提交使用 JSON 小响应，成功后即时反馈，不触发 Inertia 整页刷新。
- 用户提交后不乐观插入公开评论列表，因为内容需要审核；只显示提交成功提示。
- 移动端评论区按钮和输入框纵向排列，不能挤压主图和元数据区域。
- 评论内容必须保留换行显示，但不渲染 HTML，避免 XSS。

P1-5 明确不做：

- 不做完整评论审核后台；放到 P1-6。
- 不做举报、封禁、敏感词基础过滤；放到 P1-6。
- 不做评论点赞、评论回复、评论编辑、评论删除和评论通知。
- 不做我的评论列表、用户中心评论记录；放到用户中心与通知中心切片。
- 不做普通用户图片投稿上传；投稿功能仍在 P2。
- 不做附件上传、图片证据上传、富文本、Markdown、表情包和第三方登录互动。
- 不做相似图推荐、相似图识别或以图搜图。
- 不做下载按钮；下载按钮仍永久不作为前台默认能力。

后续阶段承接：

- P1-6：评论审核、举报、封禁与敏感词基础过滤，负责把 `pending` 评论/纠错处理为发布、拒绝、隐藏或删除。
- 用户中心与通知中心：展示我的评论、我的纠错、审核状态和处理结果通知。
- 图片入库队列与重复图提示：若纠错内容涉及相似图、重复图或 OCR 线索，后续再与数据处理能力衔接。
- 互动统计与排行榜：评论数、纠错数、活跃用户等统计在有审核和公开规则后再做。

建议开发顺序：

1. 新增评论/纠错数据表与模型关系，先保证公开图片、登录用户和状态字段约束正确。

#### 3.3.3 P1-6 评论审核、举报、封禁与敏感词基础过滤（已确认，已完成）

本切片只覆盖 P1-6 评论审核、举报、封禁与敏感词基础过滤。该确认稿已由用户确认，并已完成基础实现。P1-6 的目标是把 P1-5 产生的待审核普通评论和图片信息补充/纠错纳入后台审核队列，并补上公开评论举报、管理员处理、基础封禁和敏感词风险标记能力，避免用户生成内容失控。

开发范围：

- 后台评论审核：新增 `/admin/comments` 评论审核入口，管理员可以查看普通评论和图片信息补充/纠错记录。
- 审核动作：支持发布、拒绝、隐藏、标记删除、恢复为待审核；所有动作只改状态，不做物理删除。
- 审核备注：管理员处理评论或纠错时可以填写内部处理备注，前台不展示。
- 纠错处理边界：图片信息补充/纠错审核通过后只表示线索可信，不自动修改图片资料；真正改图片标题、日期、分类、标签、来源等信息仍由管理员/编辑员在图片管理里手动处理。
- 公开评论举报：图片详情页的已发布普通评论显示“举报”入口；登录用户可提交举报原因，游客点击举报跳转登录。
- 举报后台：新增 `/admin/reports` 举报 / 风险内容处理入口，管理员可以查看、处理、驳回、关闭举报。
- 用户封禁基础：管理员可以对用户做基础封禁和解封；被封禁用户仍可浏览公开内容，但不能提交评论、纠错、举报、点赞、收藏等会写入互动或 UGC 的行为。
- 敏感词基础过滤：新增基础敏感词规则；评论、纠错、举报提交时做简单包含匹配，只做风险标记和后台高亮，不自动公开、不自动物理删除。

建议数据模型：

- `comments.status` 扩展使用 `pending`、`published`、`rejected`、`hidden`、`deleted`；P1-6 仍不物理删除评论。
- `comments.meta` 保存审核备注、处理人、处理时间、敏感词命中结果、风险等级等后台信息。
- 新增 `reports` 表：记录举报人、目标类型、目标 ID、原因、补充说明、状态、处理人、处理备注和处理时间。
- 新增 `sensitive_words` 或等价规则表：记录词条、严重级别、是否启用、内部备注。
- `users` 增加基础封禁字段：状态、封禁到期时间、封禁原因、后台备注；先不做复杂风控画像。

后台页面与筛选：

- `/admin/comments` 列表字段：类型、状态、内容摘要、图片、提交用户、敏感词风险、创建时间、审核人、审核时间。
- `/admin/comments` 筛选：状态、类型、是否命中敏感词、用户、图片、创建时间。
- `/admin/comments` 排序：默认待审核优先，其次按创建时间倒序。
- `/admin/reports` 列表字段：举报目标、举报人、原因、状态、目标当前状态、创建时间、处理人、处理时间。
- `/admin/reports` 筛选：状态、目标类型、原因、举报人、创建时间。
- `/admin/reports` 排序：默认待处理优先，其次按创建时间倒序。
- `/admin/users` 或用户管理入口中显示用户状态，并提供封禁 / 解封基础动作。

前台交互与 UI/UX：

#### 3.5.1 时间轴浏览开发前确认稿（已确认，已完成）

本确认稿覆盖公开时间轴页面 `/timeline`、年份归档 `/timeline/{year}` 和月份归档 `/timeline/{year}/{month}`。目标是把已经入库的公开图片、相册和专题按时间脉络组织起来，帮助用户按年份、月份和重要事件考古；本切片只做数据库内公开内容聚合，不新增独立球队、赛事、赛季、对手或比赛资料表。

页面范围：

- 时间轴首页 `/timeline`：展示有公开内容的年份分组、重要月份、代表相册和精选图片，提供进入年份 / 月份归档的入口。
- 年份归档 `/timeline/{year}`：展示某一年的月份分组、公开相册、公开图片和相关专题入口。
- 月份归档 `/timeline/{year}/{month}`：展示某一年某一月的公开图片、公开相册和当月重要事件线索。
- 前台导航：时间轴页面完成后，公开顶部导航和移动端抽屉可以开放“时间线”入口；确认稿未完成前不开放入口。

数据来源与字段：

- 图片使用 `photos.event_date` 作为主时间字段；缺少 `event_date` 的图片不进入时间轴主列表。
- 只展示 `status = published` 且版权状态不是 `restricted` / `remove_requested` 的公开图片。
- 相册使用 `albums.published_at` 和相册内公开图片的 `event_date` 作为排序与归档依据；只展示 `published` 且至少包含 1 张公开图片的相册。
- 年份优先来自 `photos.event_date`；年份分类子项只作为辅助筛选和展示线索，不新增年份模型。
- 专题继续读取已启用的公开专题配置，只在与年份 / 月份有关联内容时作为辅助入口展示。

展示内容：

- 时间轴首页顶部展示页面标题、简短说明和年份快捷入口。
- 年份列表按年份倒序展示，每个年份显示公开图片数量、公开相册数量、代表图片和最近 / 重要月份。
- 年份详情按月份倒序展示；每个月份显示月份标题、公开图片数量、相册入口和精选图片网格。
- 月份详情展示当月图片网格、相册列表、可返回年份页和时间轴首页的面包屑。
- 图片卡片沿用 P1-15 高级搜索后的公开图片卡片信息：标题、事件日期、清晰度、横竖图、水印状态和必要分类 / 标签摘要。

按钮与入口：

- 时间轴首页：年份快捷入口、查看年份、查看全部图片、返回图库。
- 年份页：月份锚点 / 月份入口、查看月份、查看该年全部图片、返回时间轴。
- 月份页：查看图片详情、进入相册、返回年份、返回时间轴。
- 图片卡片点击进入通用图片详情 `/photos/{uuid}`，可以携带 `from=timeline`、`year`、`month` 等上下文参数；上下文只影响返回入口，不创建新的图片详情页。

筛选与排序：

- 时间轴首页不做复杂筛选，只提供年份快捷入口和基础统计。
- 年份页支持月份筛选、关键词、分类子项和标签的轻量筛选；筛选能力复用当前公开图库查询口径，不单独创造新搜索语法。
- 月份页支持关键词、分类子项和标签的轻量筛选。
- 默认排序为事件日期新到旧；可切换为事件日期旧到新、最新发布和综合热度。
- 无效年份、无效月份或非法筛选参数必须稳定兜底，不抛异常。

状态与边界：

- `/timeline` 在没有任何可归档公开内容时返回 200，并展示空状态和返回图库入口。
- `/timeline/{year}` 如果年份格式非法或没有公开内容，返回 404 或稳定空状态需在开发前二选一；推荐非法年份 404、合法但无内容年份返回空状态。

- 草稿、归档、隐藏、受限使用、请求下架图片和空相册不得出现在时间轴中。

## 6. UI 质量要求

1. 图片列表必须避免布局跳动：缩略图区域必须有稳定宽高比。
2. 移动端触控区域不小于 44px。
3. 搜索和筛选必须有加载状态、空状态和错误状态。
4. 所有图片必须有 `alt` 文本，优先使用标题和事件信息。
5. 不使用表情作为结构性图标，使用 SVG 图标。
6. 评论、支付、上传等表单必须有明确错误提示。
7. 深层页面必须保留返回路径或面包屑。
8. 图片详情页不自动下载原图。

#### 7.2.1 上传任务记录（当前规则）

“上传批次 / 批量整理”已收口为只读的上传任务记录。它只用于查看一次上传的汇总结果、失败文件、失败原因和异步处理状态，不承担图片编辑、分类、批量发布或归档。

- 上传任务列表显示任务 ID、上传模式、目标相册、总数、成功数、失败数、处理状态、上传者和时间。
- 任务详情显示成功/失败文件、失败原因、关联图片和处理任务状态。
- 图片编辑、分类、标签、来源链接、版权状态、发布、草稿、归档和批量修改统一在图片管理完成。
- 上传失败直接在上传结果中提示具体原因；批量上传部分失败时保留成功图片，并逐项显示失败原因。
- 任务页提供“前往图片管理”入口，不提供重复的单张编辑入口。
#### 7.2.1.1 上传后处理发布与图片状态增强开发前确认稿（已确认，已完成）

本确认稿承接后台图片批量上传和上传批次整理，不改变“本地存储 / 腾讯云 COS 两种存储方式”、8 个默认主分类或 MySQL 站内搜索边界。本切片已完成实现。

上传表单新增：

- `上传后的发布状态`：`草稿（待整理）` 或 `处理完成后自动发布`，默认 `处理完成后自动发布`。
- `批量图片分类`：未选择相册时可一次性分别选择三个必选主分类的子分类，其他主分类可选；选择自动发布时必须完整覆盖三个必选主分类。选择相册时继续继承相册分类。
- `上传后自动识别 OCR`：按需开启，默认关闭；OCR 可在图片管理中手动触发且不阻塞发布。智能标签功能已下线。

处理和发布规则：

- 上传仍立即创建图片记录和批次记录；耗时处理只进入后台队列，不阻塞上传请求。
- 自动发布等待 `metadata`、`hash` 以及 COS 模式下的 `datawanxiang_derivatives` 任务完成，并要求展示图、缩略图已写回。
- 自动发布只在标题、版权状态和三个必选主分类均满足发布条件时执行；OCR 属于增强任务，其失败不阻塞基础图片发布；智能标签已停用。
- 自动发布成功后状态为 `published`，并清除待自动发布意图；条件不满足或基础任务失败时保留 `draft`，可回到批次整理或图片管理处理。
- 已归档图片不参与自动发布；归档操作清除待自动发布意图，图片管理提供“恢复为草稿”操作，恢复后不直接公开。
- 相似候选仍由图片管理逐图手动触发，不在本切片改为全库自动扫描。

后台按钮和权限：

- 图片管理保留“发布”“归档”“识别 OCR”“计算相似候选”等动作；不再提供智能标签动作。
- 已归档记录显示“恢复为草稿”，不显示“发布”或“归档”动作；恢复后需要重新满足发布条件才能发布。
- 仅管理员 / 编辑员可上传、编辑、发布、归档和恢复图片；前台不展示草稿、归档或处理任务内部字段。

验收标准：

- 批量上传时可以明确选择草稿或处理完成后自动发布。
- 选择自动发布且分类完整、版权允许时，基础处理完成后图片自动变为已发布；缺少分类、受限或处理失败时保持草稿。
- OCR 自动开关能创建对应队列任务；关闭开关不创建自动任务，OCR 手动按钮仍可用；智能标签不再创建任务。
- 归档图片可恢复为草稿，恢复过程不会直接公开图片或保留自动发布意图。
- 数据库迁移、定向测试、全量测试和后台页面访问均通过。

本切片不做：外部搜索引擎、图片质量评分、前台 OCR / 智能标签搜索、相似图全库自动扫描、真实支付、小程序和生产环境 Worker 运维面板。
#### 7.2.2 系统设置 / 首页配置开发前确认稿（已确认，基础实现已完成）

本确认稿只覆盖后台 `系统设置 / 首页配置` 这一 P0 切片。该确认稿已由用户确认，并已完成基础实现。目标是让首页已确认的导航栏、头图轮播、分类模块、最新照片模块、专题模块和页脚可以在后台维护；本切片不开发前台首页最终页面，只提供前台首页可读取的配置基础。

页面范围：

- 主入口归属：后台 `系统运维 -> 系统设置`，在该资源内部提供 `首页配置` 分组或标签页，不新增独立后台主入口。
- 路由建议：`/admin/settings`；如 Filament 实现需要，也可使用单页设置资源或分组页面，但菜单仍显示为 `系统设置`。
- 页面目标：管理员可以维护首页固定结构中的展示内容、显示数量、排序、启用状态、跳转链接和兜底规则，前台首页读取后无需改代码即可调整模块内容。
- P0 不做拖拽式 CMS、不做自由页面搭建器、不做多套首页模板、不做 A/B 测试、不做复杂版本回滚、不做广告投放系统、不做全站 SEO 的完整后台。

数据与字段：

- 配置存储：使用通用 `settings` 表保存结构化 JSON，建议以 `group` + `key` 区分配置，例如 `home.hero_slides`、`home.category_module`、`home.latest_photos`、`home.topic_module`、`site.footer`。
- 站点基础信息：站点名称、LOGO、首页主搜索占位文案、备案信息、版权文字、联系邮箱。
- 导航配置：导航项名称、链接、排序、启用状态；P0 只显示已实现页面入口，`时间线`、`排行榜`、`支持本站`、`个人中心` 等未实现入口可先保留配置但默认不启用。
- 头图轮播：图片、标题、副标题、按钮文字、按钮链接、排序、启用状态；建议支持 3 到 5 张启用头图。
- 精选相册模块：模块标题、启用状态、显示相册数量、公开子分类导航顺序和 `更多` 跳转链接；相册内容由精选优先、最新补足规则自动生成。
- 最新照片模块：模块标题、启用状态、显示数量、手动指定置顶图片、自动补足规则、排序方式、点击目标；默认显示 15 张，桌面端三列画廊，点击进入图片详情。
- 专题模块：模块标题、启用状态、展示数量、手动指定专题、专题封面覆盖图、排序、自动补足规则、点击目标；点击专题封面进入专题详情页。
- 页脚配置：中文社媒名称、链接、图标、排序、是否启用、关于本站入口、版权说明入口、隐私政策入口、用户协议入口。
- 内部备注：可选，用于管理员记录首页配置原因，只在后台显示，不在前台输出。

按钮与操作：

- `保存设置`：保存当前配置，并让前台首页读取最新配置。
- `恢复默认`：恢复 P0 默认首页配置；需要二次确认，避免误清空人工配置。
- `添加头图` / `删除头图` / `排序头图`：维护头图轮播项。
- `添加导航项` / `禁用导航项` / `排序导航项`：维护导航展示；P0 不允许把未实现页面强行公开为有效入口。
- `选择展示内容`：从已发布图片、已发布相册、公开专题中选择首页模块展示项。
- `清空指定项`：清空某模块的手动指定内容，改由系统自动补足。
- `预览配置`：P0 可先做只读摘要预览，不要求内嵌完整前台页面预览；前台首页切片开发后再接真实预览。

筛选与选择器：

- 选择图片时，只能搜索和选择 `published` 已发布图片，排除草稿、归档、版权受限和请求下架图片。
- 选择相册时，只能搜索和选择 `published` 已发布相册，排除草稿和隐藏相册。
- 选择专题时，只能搜索和选择公开专题；若专题模型尚未落地，本切片可先保留配置结构，实际选择器随专题切片补齐。
- 图片选择器支持按标题、原始文件名、系统文件名、来源、事件日期和上传批次搜索；P0 不做复杂高级筛选。
- 相册选择器支持按相册名、分类子项和状态搜索。

排序规则：

- 导航项、头图、分类导航、专题展示项和页脚社媒支持后台手动排序。
- 最新照片模块默认按 `published_at` 倒序自动补足；手动指定图片始终排在自动补足图片前面。
- 精选相册“全部”按 `featured_at` 倒序展示精选相册，再按 `published_at` 倒序补足最新相册；子分类导航沿用该排序并按子分类过滤。
- 专题模块指定项按后台排序显示；自动补足项优先使用后台标记为推荐或最新发布的公开专题。

状态与校验：

- 每个首页模块都必须有启用状态；关闭后前台不渲染该模块，但导航和页脚作为全局结构默认保留。
- 手动指定的图片、相册和专题必须是公开可访问内容；保存时如发现内容已草稿、隐藏、归档、受限或请求下架，需要阻止保存或自动剔除并提示。
- 头图启用项至少建议 1 张；没有启用头图时，前台使用稳定默认头图或纯色安全兜底，不出现空白首屏。
- 最新照片显示数量默认 15，后台可调整；P0 建议限制在 3 到 30 之间，避免首页过长或性能过重。
- 分类模块和专题模块显示数量可配置；P0 需要有合理上限，避免后台误配导致首页撑爆。
- 外部链接需要校验 URL 格式；内部链接优先使用站内路径。
- 图片字段为空、文件不存在或图片加载失败时，前台需要有占位图，不影响页面整体结构。

权限：

- 仅管理员可以修改系统设置和首页配置。
- 编辑员可以查看配置摘要，但 P0 不允许编辑系统设置，避免误改全站首页。
- 游客和普通用户不能访问后台系统设置。
- P0 暂不做字段级权限；后续 `角色 / 权限管理` 切片再细化。

交互与 UI/UX：

- 后台使用 Filament 表单分组或标签页组织：`站点基础`、`导航`、`头图轮播`、`精选相册`、`最新照片`、`专题模块`、`页脚`。
- 表单应以“固定首页模块配置”为核心，不出现自由拖拽布局编辑器，避免把 P0 做成复杂 CMS。
- 重复项使用可排序 repeater 或等价控件；每一项展示启用开关、标题/名称、图片或目标内容、链接和排序信息。
- 内容选择器需要显示清晰的人类可读标题，不只显示 ID。
- 保存后给出成功提示；校验失败需要指出具体模块和字段，例如“最新照片第 2 张图片不可公开展示”。
- 危险操作如恢复默认、删除头图、清空指定项需要二次确认。
- 表单内容较长时，应分组折叠或分页，避免一个页面无限下拉造成维护困难。
- 前台多端适配要求在本页只做配置约束：后台允许上传适合桌面端和移动端的头图；如果只上传一张图，前台按安全区域裁切。

空状态与兜底：

- 没有首页配置记录时，系统自动使用默认配置，不报错。
- 没有手动指定最新照片时，自动取最新发布图片补足。
- 已发布图片不足显示数量时，有多少展示多少，不用空格占位。
- 没有可展示专题时，专题模块可自动隐藏或显示空状态；推荐 P0 自动隐藏，避免首页出现无意义模块。
- 没有社媒链接时，页脚不显示社媒区，但保留版权和基础链接。

验收标准：

- 管理员能进入 `系统设置` 并看到首页配置相关分组。
- 管理员能保存站点基础信息、导航、头图、分类模块、最新照片模块、专题模块和页脚配置。
- 管理员能为头图、最新照片和专题模块配置展示内容；精选相册只配置公开子分类导航，内容由相册精选状态和最新相册自动提供。
- 最新照片默认 15 张，支持指定置顶图片后自动按最新发布图片补足。
- 精选相册可配置公开子分类导航、首页内切换内容和 `更多` 跳转相册列表页；相册列表支持“精选首页/取消精选”。
- 专题模块可配置展示专题和封面，点击目标为专题详情页。
- 配置保存后，前台首页可以通过统一配置读取接口或 Inertia props 获得结构化数据。
- 未公开、草稿、隐藏、归档、版权受限或请求下架的内容不能被配置到首页公开模块。
- 无配置、无图片、图片文件缺失、模块关闭等情况下，前台首页都有稳定兜底，不出现报错或空白首屏。

#### 7.3.2 前台图库列表 `/photos` 开发前确认稿（已确认，基础实现已完成）

### 8.1 前台支持本站与档案共建者

- `/support` 展示运营支持说明、支持方案、支付结果和致谢入口。
- `/supporters` 分区展示运营守护者与档案共建者；共建者只展示已启用、未撤销、账号正常且 `is_public=true` 的公开资料。
- 公开资料只包含展示名称、简介、贡献方向和排序；不暴露授予人、角色快照、私域沟通内容等内部字段。
- 无公开共建者时显示稳定空状态。

### 8.2 登录入口与后台入口

- `/login` 与 `/admin/login` 共用 Laravel 用户、认证守卫和会话体系。
- 已登录用户导航提供个人中心和退出登录；仅 `admin` / `editor` 显示管理后台入口。
- 管理后台入口只代表具备进入后台的可能，最终由 Filament 页面和资源授权再次校验；普通用户不能依靠前台入口绕过权限。
- 前台登录成功默认进入 `/me`；旧 `/dashboard` 仅作为兼容跳转，不再进入 Starter Kit 空面板。

### 8.3 后台用户管理 `/admin/users`

- 管理员可维护基础资料、账号状态、封禁状态、档案共建者展示名称、简介、贡献方向、排序、公开开关，并执行授予、编辑和撤销共建者。
- 授予普通用户共建者时获得 `editor` 内容角色；撤销时只恢复本次授权产生的角色，原有 `editor` / `admin` 不被误降权。
- `editor` 只能访问图片、相册、分类、标签资源；不能访问用户、角色、订单、支付、审核、系统设置和安全配置。
- 管理员可维护头像、角色、启用/停用、封禁/解封、密码重置和全部会话；支持批量状态操作，并提供只读登录历史与操作审计。页面按固定三角色模型设计，不提供动态用户组、多角色并存、细粒度资源 ACL、可配置角色权限组合或通用权限冲突处理；这些能力不属于本项目需求。

### 8.3.1 用户治理与头像补充

- `/settings/profile` 支持用户上传、替换和移除头像，头像预览使用当前账号公开头像 URL；支持 JPG、PNG、WebP，最大 2MB。
- `/admin/users` 显示头像和最近登录时间；管理员可在编辑表单维护头像，并通过独立动作调整角色、启用/停用、封禁/解封、发送密码重置邮件和撤销全部会话。
- 用户管理支持批量启用、停用、封禁和解封；角色调整不能绕过活动档案共建者的角色快照规则，也不能降级最后一名有效管理员。
- `/admin/user-login-histories` 提供管理员只读登录历史；`/admin/admin-audit-logs` 提供管理员只读操作审计。
- 普通编辑员和普通用户不能访问用户治理、登录历史或操作审计资源。
### 8.4 后台分类管理 `/admin/categories`

- 8 个系统主分类和系统保留子分类不提供删除；普通无引用子分类可删除。
- 删除前检查子分类、图片和相册关联数量；有关联时阻止删除并显示具体数量和处理建议。
- 并发外键异常转换为页面通知，不能冒泡为 Livewire 500；不级联删除图片、相册或分类关系。
- 隐藏分类用于保留历史数据，并从前台公开筛选和新增内容默认选项中排除。

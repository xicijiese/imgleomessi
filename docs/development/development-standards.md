# 开发规范与协作规范

## 1. 代码规范

- PHP 遵循 Laravel 默认风格。
- 类名、方法名、变量名使用英文。
- 业务注释和文档使用中文。
- 不写无意义注释，只在复杂业务、权限、支付、队列、外部服务处写解释。
- 不把第三方密钥写入代码。
- 所有配置走 `.env`。

## 2. Laravel 规范

- 业务逻辑不要堆在 Controller。
- 复杂业务放到 `app/Actions` 或 `app/Services`。
- 队列任务放到 `app/Jobs`。
- 权限判断使用 Policy 或明确的权限方法。
- 后台 CRUD 优先用 Filament Resource。
- 前台页面优先放在 `resources/js/pages`，使用 Inertia 页面组件。
- 前台共享组件放在 `resources/js/components`，不要把页面私有组件过早抽象成全局组件。
- 前台样式使用 Tailwind CSS 和语义化组件封装，避免散落大量一次性 class 造成难维护。
- 数据库变更必须通过 migration。
- 枚举状态要集中定义，避免字符串散落。

## 3. 测试规范

采用行为测试优先：

- 登录、权限、上传、搜索、评论、支付回调必须有 Feature Test。
- 测试用户可见行为，不测试私有方法。
- 不为了覆盖率写脆弱测试。
- 一个测试验证一个主要行为。

参考 Laravel Testing：https://laravel.net.cn/docs/12.x/testing

## 4. 安全规范

- 后台必须限制管理员/编辑员访问。
- 上传文件必须校验 MIME、扩展名、大小。
- 评论必须限流和审核。
- 支付回调必须验签和幂等。
- COS 上传路径不能由用户完全控制。
- 原图访问策略必须可控。
- 删除图片优先软删除或归档，不直接物理删除。

## 5. 新手协作规范

AI 每次完成任务后必须说明：

- 改了哪些文件。
- 实现了什么能力。
- 怎么本地验证。
- 有哪些风险。
- 下一步建议。

用户不需要理解所有代码细节，但必须能理解“这个任务是否完成、如何检查、下一步做什么”。

## 6. 开发顺序建议

1. 初始化 Laravel 项目。
2. 选择 Laravel Vue Starter Kit，启用 Inertia + Vue + TypeScript + Tailwind。
3. 接入 Filament 后台。
4. 设计并迁移图库核心表。
5. 实现管理员/编辑员权限。
6. 实现图片上传到 COS。
7. 实现前台图库浏览。
8. 实现搜索筛选。
9. 加入用户登录。
10. 加入收藏、点赞、评论。
11. 加入赞助支持。
12. 加入数据万象队列处理。
13. 加入小程序 API。
